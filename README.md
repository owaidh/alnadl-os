# Alnadl Hospitality OS — Backend + Frontend

نسخة عمل كاملة من نظام Alnadl Hospitality OS، مبنية حسب:
- `Alnadl_Hospitality_Operations_Technology_Concept.docx` (التصور والنموذج التجاري)

**كل شيء في هذا المشروع فعلي ويعمل** — Backend حقيقي بقاعدة بيانات، حالة الطلب تُدار بصرامة، صلاحيات حسب الدور، عزل بيانات بين الشركاء (Multi-tenant)، وباقات تجارية (SaaS) فعالة. **الاستثناء الوحيد المتعمد هو بوابة الدفع** — راجع قسم "الدفع" أدناه.

**للتسليم الفني الكامل ابدأ من `HANDOVER.md`** — يفهرس كل مستندات `docs/` المطابقة لبنود §27 من وثيقة المواصفات (توثيق API، مخطط قاعدة البيانات، دليل النشر، خطة الاختبار، الدليل التشغيلي، دليل التدريب، جرد بيانات الدخول، ونموذج بند الضمان).

## التشغيل

```bash
node server.js
```

يفتح على `http://localhost:8787`. لا يحتاج `npm install` — كل الاعتماديات مبنية داخل Node (v22+) فقط: `node:http`, `node:sqlite`, `node:crypto`. لا اعتماديات خارجية إطلاقًا، لذا لا توجد مخاطر أمنية من مكتبات طرف ثالث ولا حاجة لصيانة `package-lock.json`.

قاعدة البيانات (`data.sqlite`) تُنشأ وتُزرع ببيانات تجريبية تلقائيًا عند أول تشغيل. لحذف كل شيء والبدء من جديد:
```bash
rm data.sqlite && node server.js
```

## الدفع — كيف يتم الربط لاحقًا

**لم يُبنَ أي اتصال ببوابة دفع حقيقية بعد، بتصميم مقصود.** كل مسار الطلب/الدفع يمر حصرًا عبر ملف واحد: **`lib/payment.js`**. لا `server.js` ولا الواجهة الأمامية يتحدثان مع أي بوابة مباشرة — كلاهما يستدعي ثلاث دوال فقط:

```js
createIntent({ orderId, amount, currency, method })
capture(intentId, ...)
refund(gatewayRef, amount)
```

حاليًا `MockGateway` هي التي تنفذ هذه الدوال (تُرجع نجاح/فشل محاكى فقط). **لربط بوابة حقيقية (مثل Moyasar أو HyperPay أو PayTabs أو Tap، وكلها تدعم السوق السعودي):**

1. أنشئ `lib/gateways/<provider>.js` ينفّذ نفس الدوال الثلاث.
2. أضف مفاتيح الـ API كمتغيرات بيئة (لا تُكتب أبدًا داخل الكود).
3. نقطة الـ Webhook جاهزة مسبقًا على `POST /api/payments/webhook` — وجّه إعدادات البوابة إليها، وتحقق من التوقيع داخل `verifyWebhook()`.
4. غيّر `PAYMENT_PROVIDER=<name>` في متغيرات البيئة.

**لا حاجة لتعديل أي شيء آخر** — لا `server.js`، لا `db.js`، لا الواجهة الأمامية. جدول `payments` في قاعدة البيانات مصمم مسبقًا ليحمل `gateway_ref` و`fees` و`status` كما ترجعها أي بوابة حقيقية، والـ Idempotency (منع تكرار الطلب عند إعادة محاولة الدفع) مُطبّقة ومُختبرة فعليًا الآن — وهذا الجزء **لن يتغير** عند الربط الحقيقي.

## ما هو فعلي ومُختبر (Backend)

كل نقطة أدناه اختُبرت فعليًا بطلبات HTTP حقيقية (`curl`) ومتصفح حقيقي (Playwright)، وليست افتراضًا:

- **آلة حالة الطلب (§10)**: انتقال غير مسموح يُرفض بـ 409، ودور غير مخوّل يُرفض بـ 403 — مطبّقة على مستوى السيرفر فلا يمكن لأي واجهة تجاوزها
- **Idempotency**: إعادة محاولة الدفع لنفس الطلب لا تُنشئ طلبًا مكررًا
- **صلاحيات + عزل بيانات (Multi-tenant)**: شريك (`PartnerAdmin`/`PartnerViewer`) يُمنع فعليًا (403) من رؤية أو تعديل بيانات شريك آخر
- **باقات SaaS (§12 من وثيقة المفهوم)**: شريك على باقة `OPERATE` يُمنع فعليًا (402) من الطلب عبر QR حتى تتم ترقيته لباقة `SMART` أو `PLATFORM` — بدون أي تعديل كود
- **محرك تسوية Revenue Share**: Gross → Discounts/Refunds → Eligible Base → Partner Share، مع سير حالات كامل (Draft → Reviewed → Partner Review → Approved/Disputed → Paid)
- **أكواد الخصم (Promotions)**: تُحسب وتُطبّق فعليًا على السيرفر عند إنشاء الطلب
- **سجل التدقيق (Audit Log)**: كل عملية حساسة (تغيير حالة، تعديل صلاحية، تغيير باقة) مسجّلة بالفاعل والوقت والسبب

**ملاحظة صراحةً:** M01 وA01 وA05 وA06 الكاملة **مبنية ومُختبرة في الـ Backend بالكامل**، لكن واجهاتها الأمامية (شاشات React/HTML) لم تُربط بعد بنفس مستوى الصقل الذي حظيت به شاشات العميل وKDS. الـ API جاهز 100%، والربط المتبقي هو عمل واجهة فقط.

جميع مزايا Loyalty/Corporate Wallet/Marketplace مُقيّدة بباقة PLATFORM فقط (§12) — تم اختبار الحظر الفعلي (402) على الباقات الأقل، ثم رفع الحظر فورًا عند الترقية، تمامًا كباقي مزايا SaaS في هذا النظام.

## الأمان — قبل الإطلاق الفعلي

هذا الكود جاهز للتطوير والعرض، وليس للإنتاج مباشرة. قبل أي نشر فعلي:
- استبدل التوقيع العشوائي لكل تشغيل (`lib/auth.js`) بسر ثابت مُدار عبر متغير بيئة
- فعّل HTTPS إجباريًا (§18)
- أضف Rate limiting على الواجهات العامة
- اربط بوابة الدفع الحقيقية (أعلاه) واحصل على شهادة PCI DSS المناسبة حسب نطاق تكاملك
- فعّل MFA لأدوار SuperAdmin وAlnadlFinance
